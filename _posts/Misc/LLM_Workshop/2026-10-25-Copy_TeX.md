사용자는 블로그 글을 선택해서 다른 곳에 붙여 넣다가 수식 부분이 이상하게 나오는 것을 봤다.

> 지금 우리 그 뭐지, 블로그 웹에서 복사 붙여넣기를 하면, 수식 부분이 예상대로 복사되지 않거든? 수정 가능해?

원인은 KaTeX가 수식 하나를 두 벌로 그린다는 데 있다. 화면에 보이는 `.katex-html`과, 스크린리더용으로 화면 밖에 숨겨 둔 `.katex-mathml`이다. 뒤쪽에는 MathML 트리와 함께 입력한 TeX 원문을 담은 `<annotation>`이 들어 있다. 브라우저의 기본 복사는 선택 범위의 글자를 DOM 순서대로 모으기 때문에, 두 벌의 글자가 한 수식 자리에서 뒤섞여 나오게 된다.

## 수식을 원문으로 바꾸는 복사 핸들러

KaTeX에는 같은 일을 하는 `copy-tex` 확장이 있다. 2022년에 KaTeX를 들일 때 `assets/katex/contrib/copy-tex.js`도 함께 들어왔지만, 로드된 적은 없다. 사용자의 요청에 대한 직접적인 해결책은 이 확장을 켜는 것이겠으나, 이를 그대로 켜면 세 군데가 맞지 않는다. 우선 이 확장은 선택을 `.katex`까지만 넓히므로, 디스플레이 수식 안에서만 선택하면 원문을 `$$` 대신 `$`로 감싼다. 또, 바꾼 글자는 `textContent`로 읽기 때문에 줄바꿈이 화면이 아니라 HTML 소스의 공백을 따른다. 마지막으로 `text/html`에는 KaTeX의 HTML을 그대로 넣는다. 셋 다 옵션으로 바꿀 수 없고 확장 자체가 100줄 남짓이라, `Copy_tex.js`는 선택을 넓혀 annotation 원문으로 바꾸는 뼈대는 그대로 따르고 이 세 군데만 다르게 짰다.

`Copy_tex.js`는 문서의 `copy` 이벤트를 받아, 브라우저의 기본 복사 대신 클립보드에 넣을 글자를 직접 만든다. TeX 원문은 수식 하나 전체에 대해서만 annotation에 들어 있으므로, 선택의 시작이나 끝이 수식 가운데에 걸려 있으면 먼저 `setStartBefore`/`setEndAfter`로 범위를 그 수식 전체로 넓힌다. 디스플레이 수식이면 `.katex`보다 한 겹 바깥인 `.katex-display`까지 넓힌다. 아래 코드는 디스플레이 여부를 `k.closest('.katex-display')`로 판단하므로, 복제한 조각에 이 바깥 요소가 들어 있어야 원문을 `$$`로 감쌀 수 있다. 넓힌 범위를 복제한 조각에 `.katex-mathml annotation`이 하나도 없으면 수식이 없는 선택이므로 기본 복사에 맡기고, 있으면 조각 안의 수식을 하나씩 원문으로 바꾼다.

```js
frag.querySelectorAll('.katex').forEach(function (k) {
  var ann = k.querySelector('.katex-mathml annotation');
  if (!ann) return;
  var tex = ann.textContent.trim();
  var display = k.closest('.katex-display');
  if (display) {
    // 여러 줄 원문(aligned 등)의 줄바꿈을 살린다
    var block = document.createElement('div');
    block.style.whiteSpace = 'pre-wrap';
    block.textContent = '$$' + tex + '$$';
    display.replaceWith(block);
  } else {
    k.replaceWith(document.createTextNode('$' + tex + '$'));
  }
});
```
{: data-filename="assets/js/custom/Copy_tex.js · 일부 발췌"}

인라인은 `$…$`, 디스플레이는 `$$…$$`로 감싼다. 디스플레이 쪽에만 `pre-wrap`이 붙는 것은 `aligned` 같은 여러 줄 원문의 줄바꿈을 살리기 위해서다.

## 화면 밖 상자에서 읽어 내는 text/plain

문단 사이의 줄바꿈이 남아야 한다는 점이 구현에서 가장 성가셨다. 바꾼 조각의 `textContent`는 HTML 소스의 공백을 그대로 따르므로, 들여쓰기 공백과 빈 줄이 덧붙고 소스에 없는 줄바꿈은 빠진다. 그래서 조각을 선택의 공통 조상 안, 화면 밖(`left:-99999px`)에 잠깐 붙이고 `innerText`로 읽은 뒤 바로 지운다. `innerText`는 렌더링된 레이아웃을 보고 블록 사이에 줄바꿈을 넣는데, 문서에 붙지 않은 요소는 렌더링되지 않으므로 `textContent`와 다를 바가 없다. 공통 조상 안이어야 그 자리에 걸린 CSS(숨김 처리 등)가 원래 선택처럼 적용되어, `innerText`가 브라우저 복사와 같은 결과를 낸다.

결과는 `text/plain`으로만 넣고 `text/html`은 넣지 않는다. 붙여 넣는 쪽은 HTML을 먼저 쓰는데, KaTeX의 HTML은 KaTeX CSS 없이는 다시 뒤섞인 글자가 된다. 원문으로 바꾼 HTML을 넣어도 Obsidian 같은 HTML→마크다운 변환기가 `\`와 `_`를 이스케이프해 버린다. 대신 수식이 걸린 선택은 서식 없는 글자로만 복사되므로, 구글 문서 같은 곳에 붙이면 링크나 굵은 글씨는 따라가지 않는다. 원문이 글에 쓴 그대로라는 점도 한계다. `katex-macros.js`의 커스텀 매크로는 펼쳐지지 않고 매크로 이름이 그대로 복사된다.

## 복사에서 빠지는 `::before` 장식 글자

수식 복사를 고치고 나서, 제목의 `Permalink` 같은 페이지 글자는 이번 변경과 상관없이 원래부터 복사에 섞여 왔다고 덧붙였다. 사용자는 그것까지 정리하라고 했다.

> 응 그래, 근데 permalink 같은 경우는 무슨 말이야? 그 예를 들어서 섹션 제목 옆에 붙는 permalink가 그대로 복사된단 말? 그렇다면 그것도 정리해줬으면 좋겠는데.

그랬다. `_main.js`는 제목마다 앵커를 붙이면서 안에 스크린리더용 글자와 아이콘 글자를 함께 넣고 있었다.

```js
// before
anchor.innerHTML = '<span class="sr-only">Permalink</span><i class="material-icons" style="vertical-align:-.2em">link</i>';
// after
anchor.setAttribute('aria-label', 'Permalink');
```
{: data-filename="assets/js/_main.js · 5e0996996 수정 전후, 일부 발췌, 따옴표 이스케이프 정리"}

제목을 선택해 복사하면 그 뒤에 `Permalink`와 `link`가 따라 나왔다. 지금 앵커에는 글자 노드가 없고 접근성 이름은 `aria-label`이 맡는다. 아이콘은 `_page.scss`의 `.header-link::before`가 Material Symbols의 `\e157`(link) 코드포인트로 그린다. `::before`의 `content`는 선택과 복사의 대상이 아니다.

같은 문제가 `i`가 적힌 안내 버튼에도 있었다. 선수지식 영역과 댓글창의 `.comment-info__toggle`은 버튼 글자로 `i`를 갖고 있었는데, 이것도 템플릿 두 곳(`semantic-prerequisites.html`, `comments-providers/custom.html`)에서 지우고 `_comments.scss`의 `.comment-info__toggle::before { content: "i"; }`로 옮겼다. 버튼 이름은 원래 `aria-label`이 맡고 있었으므로 접근성은 달라지지 않는다.

본문 h2 앞의 `§§`도 이미 `::before`로 그리고 있어서, 장식 글자는 같은 방식을 따랐다. 복사 핸들러는 수식이 없는 선택에서는 아예 동작하지 않으므로, 핸들러에서 이 글자들을 걸러냈다면 수식 없이 제목만 복사할 때는 여전히 `Permalink`가 따라 나왔을 것이다.
